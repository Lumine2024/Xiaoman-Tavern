# 剧情与数据编辑

当前文本的单一编辑入口是 `data/story.json`；原稿用于核对意图，游戏不实时读取DOCX。叙事重点是角色关系与陪伴，教程保持老酒保「来，我教你……」式自然引导，并清楚说明必要操作。

## 保持结构与引用稳定

JSON用UTF-8，不能写注释或尾逗号。只改键右侧的文字，保留根version、必需键、类型、数组数量和回答顺序。文字里的双引号需转义，换行使用 `\n`。角色story_id不是可随显示名修改的键；新增角色或分支要同步规则、文本和美术映射。

文本不决定跳转、奖惩、库存或解锁；写进一句「送你金币」不会实现机制，也不能用台词代替尚未定义的业务逻辑。回答顺序与customers中的choices效果一一对应，不能只在story里交换或增删。

教程支持既有占位符 `{drawer}`、`{liquid}`、`{amount}`、`{guest}`、`{drink}`、`{cup}`、`{ice}`、`{method}`、`{garnish}`；保留拼写与所属节点，不能把其他节点的变量随意搬来。顾客普通固定对白不因此自动支持这些变量。

| 顾客文本字段 | 用途 |
| --- | --- |
| request_text／order_note | 常规要求／指定配方对应的量化说明。 |
| topic／answers／reply | 交谈主题、按既有顺序的选项、合适回答后的回应。 |
| rumor／closing | 消息与成功出品后的收尾。 |
| opening／header | 保留原稿资料，当前界面不会完整演出全部内容。 |

原料次日改价、段二行情／段三对手及长线、具体顾客裁决均按当前规则；不能用旧稿当日涨价例句覆盖。开场不加入数字、角色口中的周目或自造欠款惩罚，保留「你还想再试一次？」的问句语气。

## 聊天池与记忆

effective存预告，ongoing存生效中，history存已结束的真实消息；按事件ID及顾客story_id组织。潮流可使用 `*` 通用句，若有该顾客专属句则优先专属。smalltalk包含通用及顾客闲聊，可附claim供船长核实；闲聊不生成数值事件，也不自动套用真实行情。

正常段二是否透露按已存在事件、相关顾客与50%抽签决定，订单内缓存抽签和台词；缺料不抽。保存／读取不能重抽同一机会或把听见传闻当成数值生效条件。船长核实同时区分将涨、已涨和未涨。

手账收录时记录当前实际说话人的story_id；同一正文由多人说过则合并来源，旧记录没有来源就显示未记录。玩家界面不揭示真假／闲聊类别。改台词后，旧手账保留旧正文；不要用猜测去补旧来源。

当前船长有五次回访、选择记忆与手账回指，选同行去码头后本局不再排入。其他完整顾客长线、漏接休眠、留座承诺及独立物件演出未接，不应仅通过补文字宣称完成。

## 交付与检查

1. 只改目标字段，检查上下文、配方数值和相邻台词的时态。
2. 执行 `python -m json.tool data/story.json` 检查语法；story_catalog专项再检查类型、覆盖、选项和变量。
3. 教程改动运行tutorial及tutorial_spotlight；事件改动运行price_intel／market_trends；涉及来源整理运行message_reasons。
4. 在1280×800与1440×900查看长台词、选项和面板，确认无截断或按钮挤压。headless不能代替阅读体验验收。

重新导入DOCX应输出到隔离位置审阅差异，不能覆盖当前手工合并的行情、裁决、角色与教程。提交说明列出修改的角色／事件／节点键与意图，数值和逻辑修改另行说明。
