# 存档与兼容

当前经营存档只接受 **v8**，格式由save_schema.gd完整校验。共享教程和界面设置独立保存，不属于经营档版本。游戏使用Godot虚拟目录 `user://`，不在源码目录写入玩家存档。

## 文件与栏位

路径由interface.json中的slots配置，以下均相对用户数据目录。

| 文件 | 用途 |
| --- | --- |
| tavern_slot_1.json至tavern_slot_4.json | 四个独立经营栏位，各有周目、同行、资产和剧情状态。 |
| tavern_auto_1.json、tavern_auto_2.json | 两个跨栏位滚动自动档。 |
| tavern_profile.json | 共享教程完成记录。 |
| interface_settings.cfg | 全屏、减少动画及总音量／音乐／环境／音效。 |
| game.log | 本次运行日志。 |
| 主档名后追加.tmp／.bak | 写入临时文件／上次健康备份，不是独立栏位。 |

Web将用户文件同步至当前站点的浏览器IndexedDB，与EXE存档不互通。换浏览器／站点、清理站点数据或使用无痕模式会影响持久化；保存后等待写入完成再关闭页面。其他平台可通过Godot用户数据目录定位文件，无需在文档提供机器绝对路径。

## 写入与恢复

关键选择、开局、挂牌、生成队列、每单出品或放弃、采购升级及进入次日时保存。正式写入前先校验内存快照，写入.tmp并flush／关闭，再回读校验；只有健康旧主档才能复制为.bak，最后将临时文件提交成主档。损坏主档不能覆盖健康备份，遗留.tmp不视为已提交进度。

加载先完整验证，再一次性应用。主档不可用时尝试.bak并提示；都不可用时保留当前内存进度，不部分加载、不静默重置。字段类型、角色／配方／事件引用、等级、计数、库存批次、日期、RNG及嵌套快照均受校验。

读取识别到v1–7旧经营档时删除该旧文件，旧备份同样处理，不再做旧版迁移。无效v8档保留以便恢复或手动处理；旧档删除规则不波及共享教程和设置。

## 接待检查点

接待中手动保存／加载，从当前未结算顾客开头重做：恢复该单开始前库存、资金、订单、RNG及既有进度。不保存半杯酒液、正在倒酒时间或判定动画。上一位已结算的收入和消耗不会重复结算。

接待中整理消息只同步正文、收藏与实际说话人字段至订单起点，不把当下半杯经济数据写进检查点。撤销删除仅限当前会话最近一批，读档和新局清除撤销缓存。教程首次量取的阅读确认也属会话状态，重新读取需再次确认。

## v8扩展与兼容

| 扩展 | 当前校验与旧v8行为 |
| --- | --- |
| run.journal_favorites | 必须为现存消息的收藏，旧v8缺失默认空；非法引用拒绝。 |
| run.journal_speakers | 正文对应合法story_id列表，旧v8缺失默认未记录；不猜来源。 |
| run.challenge | 可选十四天扩展，含成绩、阶段与D0重试快照；限制嵌套，不补造旧档成绩。 |
| run.companion_progress | 本轮锁定、待选对手、领取、分支、逐日统计与冻结结果。旧法官／教皇档缺失可用空统计，新三位同行缺失则拒绝，防止丢领取标记重复发钱。 |
| FIFO merchant_discount | 优惠批次来源布尔标记；旧／普通批次默认未优惠，成本仍按实际采购记录。 |

普通朗姆旧等级库存按现有规则合并到单池，成本不丢，退役键置零；稳定36库存键仍保留。已保存订单、due和经营RNG不追溯重排。

## 轮次、继承与重试

周目元数据与经营状态同一份提交。教程固定首轮，完成后进入普通经营；永久强化／递增难度字段为空，不因为有编号就产生能力或奖励。

十四天获胜换轮保留现金、库存／FIFO、等级、声望、顾客记忆、普通事件及连续日历；重置本轮目标、压力和同行轮内统计。下一轮同行选择可以保存恢复，取消待选不会擅改当前同行。

D0重试回滚到备货快照。富豪投资先到账、记录领取，再建立快照；同对手重试不能多领。领取记录跨换同行、重赛和自由经营保留。银行家逐日记录已处理资格／本金／利息，重开商店或读档不重复发放，D14冻结前先计息。

## 删除与保护

新建／存读档列表的占用栏位有独立删除按钮与二次确认，损坏档或仅备份档也可删除。只接受配置中手动／自动栏位，清理其.tmp、.bak和主档；当前使用的手动栏位须回标题删除。共享教程、设置及其他栏位不受影响，失败提示实际状态。

开发测试必须使用外置夹具的测试保存路径。不要删玩家目录来重置教程，不把真实用户档复制到仓库，不用历史日志代替本次验证。相关专项见[验收与边界](验收与边界.md)。
