# 开发指南

从根目录导入project.godot，使用Godot 4.5.1标准版。当前仅一个入口场景，界面主要由脚本构建；首次接手先阅读根README、AGENTS及玩法规则。

## 执行链与职责

| 入口／模块 | 负责什么 | 修改时关注 |
| --- | --- | --- |
| `scenes/main.tscn`、`scripts/game/main.gd` | 载入数据、标题、教程／选人、挂牌、接待、调酒、结算、采购和快照接线。 | 改流程检查读档入口、暂停、转场和顾客边界。 |
| `scripts/game/resource_data.gd` | ResourceLoader读取JSON并返回深复制。 | 缓存对象隔离，新增动态资源必须验证导出。 |
| `scripts/game/story_catalog.gd` | 按story_id校验、格式化并装配台词。 | 字段类型、选项数量、占位符，非法数据不部分合并。 |
| `scripts/game/daily_events.gd` | 每日事件、延迟改价、聊天池／抽签缓存、核实及鉴定。 | 已保存due、订单与RNG不能读档重抽。 |
| `scripts/game/companion_progress.gd` | 同行锁定、优惠／计息／投资、目标、冻结和存档校验。 | FIFO来源、逐日去重、D0快照和换人继承。 |
| `scripts/brewing/brew.gd`、`mistake_report.gd` | 六阶段制作、原始错误与最终失误汇总。 | 实际与要求值、豁免、收入与质量共用同一次数。 |
| `scripts/economy/pricing.gd`、`stock_ledger.gd` | 运行定价、采购批次、FIFO消耗、损耗和日报。 | 正毛利与营业额不同，同行投资／利息不造经营利润。 |
| `scripts/competition/competition.gd`、`street_rival.gd`、`challenge.gd` | 既有压力集成、卡恩与船长记忆、14天目标及机会。 | 历史v1.1参考与当前挑战不能互相冒充。 |
| `scripts/persistence/` | v8结构／业务校验、原子提交、健康备份、栏位、共享教程。 | 先校验再改状态，保护用户文件。 |
| `scripts/audio/audio_director.gd` | 场景音乐、双播放器淡变、循环、有限音效池、四路音量。 | 独立RNG，不污染经营；暂停和减少动画需清理操作循环。 |
| `scripts/ui/bar/` | 真正物件、抽屉、量筒、杯液及成酒近景。 | 杯内轮廓、冰块贴底裁切、壶杯支点及按钮可用性。 |
| `scripts/ui/focus/`、`scene_transition.gd` | 原场景镜头、输入隔离、计时启动、暂停／退出还原。 | 镜头到位才倒酒／启动判定，不用替身量筒。 |
| 其余 `scripts/ui/` | 选人、商店、手账、挑战、菜单和按钮主题。 | 真实输入、分页／焦点、两种窗口、长文本与滚动。 |

order_planner.gd保留教学及独立试算；普通经营不经过自动预留补货。run_progress.gd保存周目元数据，永久强化与递增难度接口为空。

## 数据权威

路径均在 `data/`。25份运行JSON与开发图片索引分开，不在GDScript里复制同一套数值。

| 文件 | 职责 |
| --- | --- |
| `settings.json` | 初始资金库存、时间、容差、液体键、五位同行基础能力。 |
| `recipes.json`、`rulings.json` | 当前配方与具体裁决、统一朗姆和特殊顾客要求。 |
| `prices.json` | 价格权威：原料包价、基酒等级、公式、器材／服务费；独立参考由tools/pricing.py复算。 |
| `customers.json`、`dialogue_rules.json` | 稳定角色、订单和回答效果；文本不写在这里。 |
| `story.json` | 教程／开场、顾客、聊天池、对手叙事、同行收束与共用反馈。 |
| `daily_events.json` | 事件、持续／互斥／冷却、次日改价、订单权重、临时试玩值。 |
| `companions.json` | 商人、银行家、富豪的比例与专属目标。 |
| `challenges.json` | 14天目标、计分口径、机会及挑战文本。 |
| `competition.json`、`rival_rules.json`、`rival_content.json` | 既有竞争及独立历史数值模型所需规则／引用。 |
| `street_rival.json` | 首批卡恩压力、对策开关与船长长线参数。 |
| `special_events.json`、`run_rules.json` | 已有特殊任务、周目与留空扩展。 |
| `tutorial.json` | 教学固定种子、顺序、引导范围、交接和聚光；台词在story。 |
| `interface.json`、`character_selection.json` | 标题／菜单／手账／商店／布局／保存路径、选人外观。 |
| `character_art.json`、`bar_assets.json` | 稳定角色／杯瓶等到运行资源的映射。 |
| `bar_ui.json`、`drink_colors.json`、`button_skins.json` | 物件几何／镜头、酒色、三种按钮样式及12张共享纹理。 |
| `audio.json` | 39个音频ID、交付／fallback、循环、增益、音量和场景。 |
| `asset_index_labels.json` | 仅用于生成图片索引，不进入发行资源包，不作为在用资源的证据。 |

## 常用工具

Python工具只需标准库，从工程根运行。导入旧原稿可能覆盖运行数据，先输出到临时文件比较差异；不要因有导入工具就反复全量重导。

```powershell
python tools/build_asset_index.py --project . --registry data/bar_assets.json --labels data/asset_index_labels.json --output docs/图片替换索引.md
python tools/build_pricing_reference.py --catalog data/prices.json --output tests/fixtures/pricing_reference.json
python tools/build_rulings_reference.py --catalog data/prices.json --recipes data/recipes.json --rulings data/rulings.json --output tests/fixtures/pricing_rulings_reference.json
```

pricing_reference.json的174组历史金标准和pricing_rulings_reference.json的348组当前裁决参考都属源码；只有价格规范变化才重建相应参考，不能为消除失败而改预期。tools/pricing_calculator.html是独立基础价计算器，读取同一价格目录，不能代表当前全部特殊裁决和结算修正。

酒单导入入口为import_menu.py，必须显式提供source／settings／catalog／output，可使用sources里的v0.2原稿；之后仍须合并从简裁决。import_dialogue.py保留原始格式导入能力，不是编辑当前剧情的必需步骤；新版原稿格式和手工合并内容需审阅，不能直接覆盖story。

## 合理的修改顺序

确认当前业务口径 → 改对应JSON与运行模块 → 修改或补充独立外置案例 → 运行相关专项 → 图形检查 → 同步主题指南／索引 → 必要时在源码目录外验发行包。只改可逆低风险文案无需新增镜像实现的测试，但必须验证长文本实际布局。

资源扫描要考虑JSON动态路径、条件加载和后备图；只看场景依赖会漏掉角色、音频和按钮。删除退役资源需同步引用、元数据及导出过滤。`.godot/`、日志、缓存、EXE、PCK、Web及ZIP不提交；有用的`.import`、`.gd.uid`、Shader UID和测试夹具必须保留。

开源文档不得包含本机绝对目录、个人用户名或私人日志路径。root MIT和第三方字体许可证保持完整，发布二进制时附带相关许可说明。
